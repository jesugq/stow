# Takeoff mode

`$DIR` is a directory under `~/.cursor/dynamic-mode` that has a `TAKEOFF` sentinel, else one that has a `PREPARE` sentinel. Prefer `TAKEOFF` so a new conversation can resume after Linear is not authenticated. Walk dates descending, newest first. If several of that kind, use the newest. Refuse if none. Do not choose by conversation id, and do not create a new folder. Order: analyze → clarify → handoff → prepare → takeoff. This mode's only file is `$DIR/05-TAKEOFF.md`. The others are `$DIR/01-ANALYZE.md`, `$DIR/02-CLARIFY.md`, `$DIR/03-HANDOFF.md`, `$DIR/04-PREPARE.md`.
On iff `$DIR/TAKEOFF` exists (zero-byte). Other mode sentinels: `ANALYZE`, `CLARIFY`. Mutually exclusive with those; none of them and no `TAKEOFF` means this mode is off. Keep `PREPARE` and `HANDOFF`; do not delete them. A mode command may sit anywhere in the message. If more than one of `/analyze-mode`, `/clarify-mode`, `/handoff-mode`, `/prepare-mode`, or `/takeoff-mode` appears, the last one is the mode for the whole message. Switch the sentinel first, using the swap rules already in that skill, then follow the new mode for the rest of that same message. Do not stop after creating the sentinel. Do not answer with only the `[mode]` ack when the message also asks for work. A message that is only the slash command still only toggles. `/takeoff-mode` enables or resumes this mode. If `TAKEOFF` already exists, resume: do not delete it. Swap deletes `ANALYZE` or `CLARIFY` and creates `TAKEOFF` if absent. Off deletes only `TAKEOFF`. The markdown stays. When the last command is not `/takeoff-mode`, do not write this mode's file and do not print `[mode]`.

H1 only. No frontmatter. No JSON. The first heading starts the file. Blank line after every heading and before every later one. Headings are `# 01 <5-10 word title>`, then `02`, `03`, in file order. When referring to a file, use one of two: a file in the agent cwd is `lua/libfuns/context.lua:26` (relative, colon, line on the right); a file outside that cwd is its absolute path, colon, line on the right; never `../`.
